# Changelog

## [Unreleased]

- Сирена керується двоканальним модулем реле, що імітує кнопки пульта:
  D5 — імпульс «СТАРТ», D6 — імпульс «СТОП» (300 мс, не одночасно).
  Safety-ліміт, MUTE, OTA і «Реле ВИМК» подають імпульс СТОП; при старті
  плати реле не смикаються
- Кнопку MUTE перенесено з D6 на D1 (GPIO5)
- До завантаження конфігу піни реле не керуються: раніше на модулі ACTIVE LOW
  при старті плати обидві кнопки (СТАРТ і СТОП) «натискались» одночасно
- Журнал подій: кожне натискання реле записується як `RELAY_PRESS`
  (`relay=start|stop reason=…`), у Web UI — з поясненням українською
- Підказки (i) біля полів полярності реле та LED
- Тест реле: крім циклу СТАРТ → СТОП — окремі імпульси на кожне реле
  (Web UI, `POST /api/v1/test/relay?relay=start|stop`, серіал `test start|stop`).
  Ручний СТАРТ теж обмежений safety-лімітом; під час патерна — 409 BUSY.
  Пауза циклу `relay.test_ms` тепер до 10000 мс (фактично не менше 600)

## 0.9.1 — 2026-09-16

### 2026-09-15

- Виправлено OOM-краш на живому залізі: під час активної тривоги з відкритим
  Web UI не вистачало суцільного блоку купи під TLS-контекст і плата йшла в
  reboot-loop (ядро ESP8266 робить abort на невдалий `new`). `AlertsClient::poll`
  тепер має heap-guard і пропускає опитування (`code=-100`) замість краху
- Фрагментація купи: `WebUi::sendJson` для малих відповідей (<768 Б) серіалізує
  у стековий буфер і віддає chunked-передачею — нуль купи на 5-секундному
  опитуванні `/status`, без realloc-churn; найбільший блок більше не сповзає
- Автоматизація версії: єдине джерело — файл `VERSION` у корені;
  `tools/build_stamp.py` підставляє `AIRALERT_VERSION` і `AIRALERT_BUILD`
  (жива build-дата) на кожній збірці замість зашитого прапорця в platformio.ini

### 2026-09-07

- Провайдер тривог: alerts.in.ua → **ukrainealarm.com API v3**
  (`GET /api/v3/alerts`, ключ у заголовку `Authorization`). Стрімінг-парсер
  по регіонах; INFO-повідомлення пропускаються
- Рівні повітряної тривоги: жовтий (дрони) — окремий тип `air_raid_yellow`
  з власним профілем сигналів (увімк/пріоритет/патерни/нагадування),
  червоний/нерівневий — `air_raid`; червоний домінує на одній тривозі, зміна
  кольору не озвучує «відбій». Дашборд показує 🟡/🔴
- Каталог локацій з `/api/v3/regions`: 1605 записів у PROGMEM (з громадами —
  тривога громади дає часткове покриття району/області), у Web UI як і
  раніше області/райони/міста; Крим = 9999
- 401 від API — це його rate-limit (~3 прийнятих запити/хв на ключ, решта —
  401 без тіла, як і на невірний ключ; заміри в docs/RESEARCH.md). Прошивка
  на 401 просто опитує далі; «unauthorized» + API_401 + 5-хв backoff лише
  після 15 поспіль. Дефолти: опитування 20 с, «застарілі» після 90 с; config
  schema 2 — збережені 15/60 мігрують у 20/90
- Емулятор `tools/alerts_emulator.py` у форматі ukrainealarm (`start air_raid 75 yellow`)

### Повне ревью коду (2026-09-07)

- Реле мовчки «вмирало» після збереження конфігу під час патерну:
  `RelayController::begin()` лишав кешований `on_=true`, тож наступний
  `apply(true)` був no-op і асинхронний дедлайн безпеки не зводився
- Індикатор тривоги (D0) залишався темним після збереження конфігу під час
  тривоги — той самий застарілий кеш в `Indication::begin()`
- OTA міг назавжди підвісити пристрій із вимкненою сиреною (веб-сервер ядра
  крутиться в `_uploadReadByte()` на half-open з'єднанні): доданий
  SYS-дедлайн 5 хв на `Ticker` → перезавантаження на стару прошивку
- 304 після невдалого парсингу застосував би недобудований знімок
  (Invariant 6): при помилці парсингу скидається валідатор і кеш
- `/api/v1/scan` (блокуючий ~2 с скан) вимагає автентифікації поза
  портал-режимом; `activeView` очищується при зміні локацій;
  `static_assert` на бітмаски типів; у `/api/v1/system` прибрано застаріле
  «155 locations»; повторний вхід у Web UI більше не дублює опитування
- Другий прохід: опитування API не стартує, поки реле УВІМК (синхронний TLS
  розтягував ON-фазу сирени до тривалості запиту); парсер відповіді — ліміт
  20 с загалом + 5 с без даних замість фіксованих 8 с; `static_assert` на
  порядок `LocationType` проти згенерованої таблиці; підказка в UI про ліміт
  API; доки: реальний TLS-ланцюжок для `BEARSSL_SSL_BASIC` (RSA WR1→R1,
  перевірено), дефолти 20/90 у CONFIGURATION.md

### 0.9.0 — 2026-08-21

Перша повнофункціональна pre-release збірка. Фази 0–9 за docs/SPEC.md.

- Ядро: AlertEngine (підтвердження 1/2, escalation, multi-location),
  LocationMatcher (ієрархія, каталог 155 локацій), PatternScheduler,
  NotificationEngine (черга, пріоритети, mute-політики), RelayGuard,
  StartupPolicy (анти-reboot-loop), 100 native-тестів
- API-клієнт: BearSSL + GTS trust anchors, TLS session resumption,
  If-Modified-Since/304, backoff 15→120с, стрімінг-парсинг з фільтром
- Персистентність: атомарний конфіг зі схемою і міграцією, циркулярний
  журнал подій 2×16КБ, state-snapshot для перезапуску під час тривоги
- Web UI (uk): дашборд зі stale-станом, локації, профілі сигналів, реле,
  журнал, діагностика, OTA; сесії X-Auth, lockout на login
- Provisioning: AP + captive portal, recovery AP+STA, wifi/forget
- OTA: upload + HTTPS URL з обовʼязковим SHA-256
- Прошивка: 528 КБ (51% IROM), RAM 47%, heap у роботі ~27 КБ
